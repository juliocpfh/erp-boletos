# Arquitetura

## Camadas
| Camada | Arquivos | Fala com |
|---|---|---|
| Interface (HTML em texto) | `docs/js/telas.js` (rotas `TELAS`) e `docs/js/telas/*.js` (um arquivo por assunto), `docs/js/formularios.js`, `docs/css/estilo.css`, `docs/index.html` (com a CSP: só scripts do próprio site e só os domínios usados na `connect-src`) | chama `regras.js` dentro de `alterar()`; lê `E.d` direto para desenhar |
| Aplicação (estado, rotas, eventos) | `docs/js/app.js` | `telas.js` (TELAS; repassa FORMULARIOS de `telas/envios.js` e ACOES de `telas/acoes.js`, que absorvem `FORMULARIOS_BANCO`/`ACOES_BANCO` de `telas/banco.js`), `armazenamento.js`, `backup-seguro.js`; parâmetros do endereço passam por `calculos.js` → `sanearParametros` |
| Regras de negócio | `docs/js/regras.js`, `docs/js/conciliacao.js` (banco fase 2), `docs/js/alertas.js`, `docs/js/contratos.js` | `calculos.js`; recebem o banco `d` como parâmetro (não tocam em disco nem em DOM, exceto `contratos.js`, que só gera texto/HTML/DOCX) |
| Cálculo puro | `docs/js/calculos.js` | nada (só funções) |
| Dados | `docs/js/armazenamento.js`; nuvem (no ar): `nuvem.js` (`Sincronia`: `alterar` em `app.js` passa por ela quando `E.nuvem` existe), `pasta-nuvem.js` (`E.pasta` vira pasta virtual da API), `cofrinho.js` (cópia cifrada no IndexedDB), `migracao.js`; banco: `docs/js/banco.js`, `docs/js/banco-fase2.js` (clientes da ponte, só JSON por HTTP) | File System Access API e IndexedDB (atalho da pasta); a ponte `ponte-c6/` (em `?teste`, a ponte simulada dentro do site com `simulado-banco.js`) |

Regra prática: `regras.js`, `conciliacao.js`, `calculos.js`, `nuvem.js`, `pasta-nuvem.js`, `cofrinho.js`, `migracao.js`, `banco.js` e `banco-fase2.js` rodam no Node (são os testados em `tests/`). `telas.js`, `telas/` e `app.js` só rodam no navegador. Nas tabelas abaixo, "`telas.js` → X" é o grupo das telas: X fica em `docs/js/telas.js` ou num arquivo de `docs/js/telas/` (`node tools/mapa.mjs X` diz qual).

## Modelo de dados
- O banco é um objeto: `{ formato: 'imoveis-v1', revisao, seq, historico, listas, estilos_alertas, config_banco, <tabela>: [ ... ] }` (`estilos_alertas`: aparência escolhida para cada tipo de alerta; `config_banco`: integração com o C6, sem segredos: `normalizar` apaga `senha_ponte`/`ponte_url` se aparecerem).
- As tabelas são as chaves de `TABELAS` em `docs/js/regras.js` (ex.: `imoveis`, `contratos`, `cobrancas`, `faturas`, `emitentes`, `participacoes`, `fiadores`, `iptus`, `ressarcimentos`, `fechamentos`, `aditivos`, `solicitacoes`, `guias_impostos`, `movimentacoes_banco`, `pagamentos_banco`…). `bancoVazio()` cria uma lista para cada uma.
- `id` de cada registro vem de `d.seq[tabela]` (em `inserir`). Na nuvem, `seq` não sincroniza: cada aparelho usa uma faixa reservada (`Sincronia.faixas`, `POST dados/faixa`) para não repetir código sem internet. Dinheiro em **centavos inteiros**; datas `'AAAA-MM-DD'`; competência (mês de uso) `'AAAA-MM'`.
- `normalizar(d)` em `regras.js` migra bancos antigos ao abrir (campos renomeados, tabelas novas). Na nuvem, `Sincronia.atual()` aplica em toda vista e `enviarAjustes()` manda as correções à nuvem uma vez, quando o administrador entra (`ajustesParaNuvem` em `app.js`; os outros só veem na própria tela).

## Fluxo típico: confirmar um pagamento
1. Tela `#/cobrancas` (`telas/cobrancas.js` → `telaCobrancas`) desenha o form `data-form="pagamento"`.
2. `app.js` captura o `submit` e chama `FORMULARIOS.pagamento(form)` em `telas/envios.js`; um erro lançado abre a janela "Entendi" (`aviso(…, 'erro')` → `janelaErro`).
3. `FORMULARIOS.pagamento` valida e chama `alterar((db) => R.registrarPagamento(db, id, data, …))`.
4. `alterar` (`app.js`) põe a gravação numa fila (uma por vez; enquanto roda, o botão `[data-acao]` fica desabilitado, `data-ocupado`); `alterarAgora` relê `imoveis-dados.json` (sumiu: `ERRO_ARQUIVO_SUMIU`, nada é gravado); se a `revisao` do disco mudou, troca `E.d` pela versão do disco; clona; aplica a função.
5. `registrarPagamento` usa `C.liquidar` e grava via `atualizar` → `registrar` adiciona a linha em `d.historico`.
6. `alterar` soma `revisao`, grava o arquivo (`S.gravarBanco`), faz o backup diário (1x por sessão; nome pela data local `hojeIso()`, como o espelho) e espelha no backup seguro, se ligado.
7. `mostrar()` redesenha a tela a partir de `E.d`.
